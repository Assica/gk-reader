## 1. 最有价值的产出：CTC 强制对齐的 Viterbi 终点 bug

**一句话**：`_viterbi_states()` 回溯起点用的是**全部状态上的 argmax**，模型在句子中间
最自信时路径就"提前结束"，后面所有词分不到任何帧，`wordTimes` 里就出现 null——
这不是 CTC 低置信，而是强制对齐没有走完整句。

证据（`GK-001 p7`，T5 硬编码的那一页）：

```
S=41（20 个 label 的 CTC 图），argmax_state=28，last_label=39，trailing_blank=40
→ "cheese." 零帧 → wordTimes 里是 null
修复后：[[0.04,0.23],[0.234,0.53],[0.534,1.07],[1.074,1.5],[1.504,2.04]]，5 个词全部有帧
```

**改的 6 行**（`tools/ctc_align.py`，`_viterbi_states` 结尾）：

```python
-    i = int(np.argmax(score))
+    # Forced alignment must consume the whole transcript: the backtrace may only
+    # start on the last label state (S-2) or the trailing blank (S-1).  Starting
+    # from argmax(score) over *all* states ends the path wherever the model is
+    # most confident; every word after that point then has zero frames and shows
+    # up as a null in wordTimes even though the audio is fine.
+    if S > 2:
+        tail = score[S - 2:]
+        i = (S - 2 + int(np.argmax(tail))) if np.max(tail) > NEG / 2 else int(np.argmax(score))
+    else:
+        i = int(np.argmax(score))
```

影响：修复前全库 **766 页**至少有一个 null（`fix-new.log` 的 filled=766 页）；修复后
raw CTC 里只有 **55 页**有 null（其中 48 页是无词框页，真正有词框的 null 页只有 **7 页**）。
样例：GK-001 2→0，GK-004 8→0，GK-053 52→0，G1-010 45→0；只有 `T < label 数` 的页
（G1-061/G1-107 这类 40+ 词/页）仍有 null，按规则整页丢弃。

> 这一步是 zero-interp + 74/74 能同时成立的唯一办法：不修，T5 硬编码的
> `GK-001 p7` 会因"cheese"是 null 被整页删掉，原 74 项不可能全绿。

## 2. 规则（与代码一一对应）

`tools/fix_wordtimes.py` 里 `_check()`，命中任意一条即 `p.pop("wordTimes")`：

1. 非句子文本（PDF 印前批注）→ **清空 text、wordBoxes 置 null、删 wordTimes**（页图保留）；
2. `wordBoxes` 为 null；
3. `len(wordTimes) != 词数`；
4. 任何一个词是 `null` —— **不插值**；
5. 任何一个词段 `< 60ms`；
6. 任何一个词段 `> 2s`（正常英文词到不了 2s，超过就是把静音/别的话拉进来了）；
7. 整页词速 `< 1` 或 `> 8` 词/秒（文字和音频根本对不上）；
8. span 非正 / 越界 / 非严格递增。

**脚本没有任何填充函数**：没有 `_split_run` / `_uniform`，也不改写任何 span；保留页的
`wordTimes` 与 raw CTC 完全相等（第 5 节有逐页比对）。
