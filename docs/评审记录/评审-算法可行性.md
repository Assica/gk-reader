# 修复方案技术可行性评审（reviewer-data）

日期：2026-11-14 · 实测环境：onnxruntime 1.32.0 CPU / intra_op=4 / i5-12400 12 核 / 64 GB
模型：`.work/models/wav2vec2-960h/model.onnx`（wav2vec2-base-960h int8）
脚本与原始输出：`.work/reviewer-data/`

## 0. 结论

**部分可行。** 整本对齐的*精度*实测没问题；但方案按原样落地有两个硬伤：
(a) ONNX encoder 内存随音频长度超线性（120 s → 6.7 GB，库内最长书 266 s → 外推 24 GB）；
(b) R1 的"字母偏移"只按方案描述上，只能救 201/379 页，因为真正的根因方案没识别到——
`clean_sentence` 把含弯引号的整词丢掉（403 页 / 2017 词）、`word_boxes` 的 run 正则同样丢这些词、
`select_sentence` 有 5 行窗口上限（379 页里 244 页 ≥6 行，64%）。

### 1.3 内存 / 时间（单次前推，峰值 = PeakWorkingSetSize）

| 音频 | 前推 | 峰值内存 | RTF |
|---|---|---|---|
| 5 s | 0.27 s | 240 MB | 0.053 |
| 30 s | 2.42 s | 669 MB | 0.081 |
| 60 s | 6.82 s | 1215 MB | 0.114 |
| 120 s | 14.79 s | **6688 MB** | 0.123 |
| 210 s | 34.0 s | **14879 MB** | 0.162 |

- 长度×2（60→120 s）内存×5.5：self-attention O(T²)。
- 全库 239 分钟音频，串行 encoder ≈ 29 分钟；8 并发需 ~8×(中位 1.3 GB / p90 8 GB) → 16 GB 机器必 OOM。
- 9 本书 >180 s（最长 266 s，外推 ~24 GB）。

### 1.4 Viterbi 不会爆

S = 2L+1。最大书 435 词 → L≈2113 → S≈4227；T≈13300 帧 → back 矩阵 int8 = 56 MB。
实测 viterbi：118 词/65 s = 0.1 s；231 词/150 s = 0.5 s。**内存瓶颈只在 encoder。**

### 1.5 污染范围（实测）

- 插入 12 词"批注页"（G1-062 第 3 页前）：批注页占 26.40–28.98（抢了下一页开头 2.58 s），
  末页 end +4.02 s，其余 5 页 Δ=0.00。**污染向后、局部。**
- 把某页文字**重复一遍**（模拟 R3 跨页重复）：重复页抢走 6.18 s 真实音频 →
  下一页整页拿不到帧（缺失）→ 其后页位移最多 **−11 s**，32% 词 >0.3 s。**污染向后、直到书尾。**

### 1.6 建议方案（分块 encoder，不用整本一次前推）

30 s 窗 / 25 s hop，只保留非重叠段帧，拼 logits 后**一次** Viterbi：

| 书 | 帧覆盖 | 帧级 argmax 一致 | 词起点差 |
|---|---|---|---|
| G1-062（65 s，无重复） | 100% | 90.6% | 中位 0 / p90 20 ms / max 20 ms |
| G1-061（150 s，含重复页） | 100% | 84.4% | 中位 0 / p90 260 ms / max 9280 ms |

峰值内存封顶 0.67 GB（30 s 块），耗时 4.4 s vs 5.2 s（65 s 书）。
G1-061 的 9.28 s 大偏差来自**重复文字的双稳态**：logits 只要变 15%，重复块归属就翻。
→ chunk 边界尽量落在静音段（现成 `segments` 可用），并把"整本内页文字完全相同"先去重。

## 2. R1 字母偏移

### 2.1 30 页抽样（seed=20261114，每本最多 1 页；分母 379 个 wordBoxes=null 页）

| 口径 | 一致页 |
|---|---|
| A == B（现行 clean + 现行 run 正则） | 9/30 |
| A == B'（两层对称归一化） | 26/30 |
| 新算法最终出框 | 29/30（exact 27、repair 1、none 1） |

全量：379 页 → **378 页出框**（exact 335 + repair 43 + none 1）。
全库：**1441/1442 = 99.9%**（方案目标 ≥95%）。
唯一失败：GK-035 p11（"Pop!" 视觉层 0 个 run，矢量字）——任何算法都救不了。

### 2.2 消融（在 379 页上分别只改一处）

| 改动 | 出框 |
|---|---|
| 只修 clean（弯引号/逐字符剥离） | 0 (0%) |
| 只放宽 run 正则 | 0 (0%) |
| 两者都改，但仍走旧 `merge_to_tokens` | 0 (0%) |
| 两者都改 + 字母偏移 + 视觉 run 为 canonical | 378 (99.7%) |

原因：`select_sentence` 的窗口上限 `range(i, min(len(lines), i+5))` —— 379 页里 **244 页 ≥6 行**（64%），
永远匹配不上；这是方案没提到的第二个根因。

### 2.3 回归

- 1063 个已有词框页：**933 页框完全一致**，IoU 中位 1.000（>0.9 的 933 页）。
- 129 页词数变多（正是今天被吞掉的词），0 页变少。
- 相邻框重叠（379 页上）：不合并拆词 → 出框 335 页，其中 **51 页相邻框重叠**；合并（视觉 run 为准）→ 378 页、仅 3 页重叠。

### 2.4 文字层吞词（方案未提，用户可见）

`build_library.py:72` `if any(ord(ch)<32 or ord(ch)>126 for ch in tok): continue` 整词丢弃：
**403 页 / 2017 词 / 7478 字母**。例：G1-007 p4 存库 "Ant met a bird. you said the bird. I said the ant."
实际 "Ant met a bird. \"Can you fly?\" said the bird. \"No, I can't,\" said the ant."
自我掩盖：视觉 run 用 `[A-Za-z][A-Za-z'’,.!?\-]*` 也丢掉同样的词 → 字母流一致、框看着是对的。

### 2.5 比例分配退路

A!=B 的 178 页：字母数相对差 中位 4.8%、p90 11.8%、max 100%。
152/178 页文字是视觉字母流的**子序列**（只多不少）→ 应先"词级 LCS 剔除多余词再重映射"（实测救回 43 页），
比例分配只当最后退路，且只在 `boxQuality: approx` 上用。

## 3. 词/秒阈值

1438 页词速：p50 2.72、p90 5.90、p95 8.91、p99 17.26、max 31.3。

| 阈值 | 命中页 | 其中 ≤6 词 | ≥8 词 | ≥20 词 |
|---|---|---|---|---|
| >4.5 | 214 | 4 | 209 | — |
| >6.0 | 142 | 3 | 138 | 80 |
| >8.0 | 93 | 3 | 89 | — |

方案说 67 页，实际同阈值是 142 页。3 个 ≤6 词的高词速页本身也不可信（4 词 0.43 s）。
6 不会误杀（儿童朗读 2–4 词/秒，6 = 360 wpm），但漏检 70+ 页。
建议：① 词数≥8 且 >4.5（209 页）② 实际时长 < 0.5×(词数/2.7)（163 页）；上 R2 后改用 CTC 指标。

## 4. 方案漏掉的坑

1. 文字层吞词 403 页（R1 的前置；不修则 R2 页区间系统性偏短）。
2. R1 改完 `wordBoxes.words` 数 ≠ `text` token 数 → `align_library.py:64-67` 丢 wordTimes（53 页）。
3. 拆词不合并 → 335 页里 51 页相邻框重叠（一个视觉词两个热区，各播半词）；合并 → 3 页。T4 已改 Voronoi 吸附，测试抓不到。
4. 页区间=首词~末词：页间停顿（实测 0.02–4.84 s）被切；4 个空文字页（R4 后 3 个）无词→无区间→不可播。
5. 重复文字让对齐双稳态（chunk 扰动 9.28 s）；R3 必须先做且必须"先去重再拼"。
6. 没有 per-book 全局失败检测器：文字缺失会让后续词被压缩，整本错（污染向后累积）。
7. `widen()`/`check_wordtimes.py` 是逐页的：必须先转页内相对时间再按页 clip_len widen。
8. 内存/并发：naive 整本前推 8 并发必 OOM；266 s 书 ~24 GB。
9. `pick_alignment`/`repair_page_audio.py`/`segments`/`alignMethod` 变死代码，qa/audit 仍读。
10. 方案自己的数字与库不符（375 vs 379、67 vs 142、10–20 分钟 vs 实测串行 29 分钟）。

## 5. 只改一处

**把 R1 做对，而不是做方案描述的字母偏移**：视觉 run 为 canonical + 字母偏移 + 拆词合并，
并同时把 `clean_sentence` 的整词丢弃改成逐字符剥离、`word_boxes` 的 run 正则同步放宽。
收益：378/379 无框页 + 403 页文字恢复；零模型依赖、1 分钟跑完、可快照回退。
R2 风险最大，应放在最后且必须分块。
