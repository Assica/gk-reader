# 数据层问题修复方案 v2

> v1 被三位评审推翻。本文记录 **v1 错在哪**、**真正的根因是什么**、**改什么**。
> 数字全部来自独立复算（`.work/watchdog4/`、`.work/review/`）。

---

## 0. v1 的五处事实错误

| # | v1 的说法 | 实测 | 后果 |
|---|---|---|---|
| E1 | 字母流一致率 95%，R1 可救 375 页 | 按 v1 自己的算法只有 **1/379**；加 run 过滤器后 **201/379**；95.8% 是"两个解析器读同一层文字"的假象 | 验收标准（词框 ≥95%）达不到，实际天花板 87.7% |
| E2 | R1 做完逐词可用从 941 升到 1300+ | 375 个无框页**全部没有 wordTimes**，`playWord` 会退回 `playSentence`。R1 只把"点了没反应"变成"读整句"，**可用页数仍是 941** | 目标定错了 |
| E3 | R2 整本对齐，Viterbi 内存会爆 | Viterbi 只要 3.6–25 MB；**爆的是 wav2vec2 encoder（attention O(T²)）**：120s → 6.7 GB，266s → ~24 GB。库里 28 本 >120s | 方案前提错，必须分块（30s 窗 / 25s hop ≈ 0.7 GB） |
| E4 | `GK-045 p4/p5/p8` 只有批注 | 三页都有正文：`Look at my hat. My hat is big.` 等；`G1-080 p4` 有 `A big red thing made a noise.` | v1 的验收条件会把 **4 页真正文永久删掉** |
| E5 | 3 本书有重复句，同页连续重复要折叠 | 3 本全是**跨页**复沓（真重复）；全库有 **38 处同页连续重复**，34 处是拟声（`Crack!` `Yum!` `Trip-trap.`） | 折叠会破坏合法内容 |

另外 v1 的"词/秒 > 6"阈值切在 p90，会**误杀 27 个当前正常工作的页**（如 `G1-006 p7` 6.0、`GK-059 p5` 7.9）。改 **8**（0 误杀）。

## 1. 真正的根因（按影响面排序）

### C1 文字清洗把带弯引号的词整词丢掉 —— 影响 30% 的页

`tools/build_library.py`：

```python
if any(ord(ch) < 32 or ord(ch) > 126 for ch in tok):
    continue          # ← 整词丢弃
```

绘本对白大量使用 `’ “ ”`（U+2019 等）。于是 `sister’s`、`“Hello,` 整个词被删。

**实测影响**：**434/1442 页（30.1%）** 的文字与页面上印的字不一致；`G1-061 p7` 的 `sister's`、`p8` 的 `brother's` 就是这么丢的。

**修法**：换字符前先做归一化（`’→'`、`“”→"`、`—→-`），只删真正的控制字符；不要因为一个非 ASCII 字符丢掉整个词。

### C2 `pick_alignment` 只挑"最均匀的窗口"，把书头书尾丢了

```python
for start in range(0, len(segs) - n_pages + 1):
    win = segs[start:start + n_pages]
    score = d.std() / d.mean()      # 越小越好
```

它挑的是**时长最均匀的连续 n 段**，而不是"覆盖整本书"的那 n 段。

**实测影响**：

- **37 本**书的页区间覆盖不到本书语音段的 70%，最差 `G1-061`：页区间合计 31.5 s / 语音 110.4 s（29%）
- **27 本**首段前有 >15 s 未分配语音，**29 本**尾段后 >15 s 未分配（`G1-107` 开头丢了 152 s）
- 这正是"48 个词配 2.17 秒音频"的来源——不是文字长，是这一段音频根本没被分配到正确的页

**修法**：不再找"最均匀窗口"，改成**把整本书的语音段按页序完整分配**（动态规划：每页至少 1 段，最小化页时长与页文字量的偏差）。

### C3 视觉 run 的分组器丢 27.9% 的 run

`word_boxes()` 里 `re.fullmatch(r"[A-Za-z][A-Za-z'’,.!?\-]*", w)` 把以弯引号开头/结尾的 run 全部拒绝（1876 个 run、22.8% 的字母）。这些就是 `“Hello,”` `sister’s` 这类。

**实测影响**：379 个无框页中，**361 页连 textBox 都没有** → 点图完全没反应（连"读整句"都没有），这是最伤体验的一类。剩下 14 页能读整句，4 页空文字。

**修法**：run 规范化后再匹配（同 C1），并把"词"的判定从"正则整词匹配"改成"含至少一个字母"。

### C4 批注页整页清空

`build_library.py` 命中 `interior art|Art:|Adjust` 就 `text=""`、`wordBoxes=null`。但批注行和正文行**在同一页**。

**修法**：行级过滤——只删命中批注特征的那几行，剩下的正文保留。

## 2. 修复顺序（有原子性要求）

> **关键约束**：C1/C3 改的是文字与词数。任何一页的词数变了，它的 `wordTimes` 必须重算，
> 否则 `playWord` 会因为 `wordTimes.length !== n` 静默退回读整句。
> 实测：只改清洗、不重对齐，会让 **90 个当前可用的页**静默退化。

因此顺序是：

| 步 | 内容 | 影响 | 验收 |
|---|---|---|---|
| **P1** | C1 引号归一化 + C3 run 分组 | 文字与词框重建 | 与 P2 同一批提交 |
| **P2** | C2 页区间重算（DP 完整分配） | 全部 180 本的 `pages[].audio` | 页区间覆盖率：每本 ≥95% 语音段被分配 |
| **P3** | 重跑词级对齐（Viterbi 已修） | 941 页全部重算 | 词/秒 >8 的页 = 0 |
| **P4** | C4 行级批注过滤 | 4 页 | 4 页正文全部恢复，批注残留 = 0 |
| **P5** | 全量验收 | — | 见下 |

**原子性**：P1+P2+P3 必须在同一次重建里完成，中途不发布。因为它们共同决定 `text` / `wordBoxes` / `wordTimes` 三者的索引一致性。

---

## 3. 验收标准（替代 v1 凭空的 95%）

| 指标 | 目标 | 怎么测 |
|---|---|---|
| 页文字与印刷层一致 | ≥ 95%（现状 69.9%） | 字母流比对（`word_boxes` 过滤后） |
| 有词框的页 | ≥ 1370/1442 | `audit_content` 式统计 |
| **同时有词框和 wordTimes 的页** | **≥ 1200（83%）** | 这才是"真能逐词点读"的口径 |
| 点图无反应的页 | 0（现状 361） | 每个无框页必须有 textBox，否则算失败 |
| 页区间覆盖率 | 每本 ≥95% 语音段被分配 | 新脚本 |
| 词/秒 >8 的页 | 0 | 统计 |
| 批注页正文 | 4 页全部恢复 | 人工核对 4 页 |
| 现有测试 | 108 断言全绿 + 变异 11/11 | `webtest` + `mutation` |

---

## 4. 不再做的事

- **不做 R3 折叠**：3 本跨页重复是绘本复沓；38 处同页重复里 34 处是拟声词，折叠会破坏文字与音频对应
- **不用"词/秒 >6"筛页**：会误杀 27 个正常页，改用 8
- **不做整本一次对齐**：encoder 在 120s 时 6.7 GB，必须 30s 窗分块（这条 v1 说错了，但结论仍是不做整本）

---

## 5. 回退

每步前生成 `library/` 的 sha256 清单（1983 个文件）。任一步验收不达标 → 按清单还原，不带着半成品继续。

## 6. 页码口径（评审指出的坑）

`book.json` 里 `pages[].n` 是 **PDF 页码**（4–11 或 4–20），UI 页序是数组下标（0 起）。
两者差 3（GK/G1 都是正文从 PDF p4 开始）。

**本文所有页码一律写 PDF 页码 `n`，UI 页另注。** 测试断言必须用 `n` 反查下标，不能直接拿 UI 页号比。
